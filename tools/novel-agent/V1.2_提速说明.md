# WordLetter 小说生产 Agent V1.2 · 高效模式（2026-11-06）

> **安全提醒：正在运行的 V1/V1.1 不要中途替换文件。** 本版本独立解压。待旧任务完成或已停止，再使用下述续跑入口。不会改 D1、网站、订单、权益。

## 主要问题

以 8 章、约 130 词的新书为例，旧 V1 的独立 Codex 请求约为 **1 + 6 + 8 + 8 = 23 次**（大纲/词卡/章节/章节审校）。每次独立请求都需要启动 Codex 并经受可能的网络重连，导致总耗时较长。

## 具体优化

1. **词卡大批次：** 新项目高效模式默认每批 44 个义项，130 个目标义项从约 6 次减少到约 3 次。旧项目已经开始分批时保留原批次，防止 ID 对不上；若已有完整 merged.json 则直接复用。
2. **相邻两章同次创作：** 将 8 章的 8 次请求减少到 4 次；依然生成 8 个独立 JSON，每章仍要满足最低篇幅、人物因果、每词原义项和自然中英嵌入要求。某章已经保存，绝不重写它。
3. **相邻两章同次独立 AI 审校：** 从 8 次降到 4 次；仍按两个独立文件输出每一个使用过的 wordId 的审校结论，保留 P0/P1/不确定项，不等同人工终审。
4. **断点兼容：** 默认读取原项目已有提纲、词卡、章节、审校 JSON，跳过已完成阶段；不改现有 bookId。
5. **耗时记录：** 新运行阶段写 `codex_timings.jsonl`，记录阶段、成功/失败退出码、耗时，便于定位瓶颈。
6. **减少终端重复输出：** 提示 Codex 将完整正文/JSON 直接存盘，终端不要重复回显全文。

以尚未开始的新 **V1** 8章/130词项目作示例，调用数量可能由约 23 次降至约 **12 次**（大纲 1、词卡 3、章节 4、审校 4），**不是实际耗时对比或保证加速 50%**。V1.1 新项目另含剧情主编前置审核调用。网络重连、超时和模型长文本输出仍可能延迟生成，两个章节同时写若上下文超限可能需改用普通模式逐章重试。

## Mac 运行

下载 ZIP 并解压为 `WordLetter-Novel-Agent-Fast-V1.2`，放到 `~/Documents/`，与现有 `WordLetter-Novel-Agent` 文件夹并列，**不要覆盖旧版**。

### 继续已保存的旧项目

在确认旧任务已停止后，终端执行：

```bash
cd ~/Documents/WordLetter-Novel-Agent-Fast-V1.2
bash 快速续跑.command
```

会显示旧项目列表供选择，然后调用 `python3 novel_agent.py run --project 原项目路径 --fast`；不会自动发码或上传生产库。

也可直接指定项目：

```bash
python3 ~/Documents/WordLetter-Novel-Agent-Fast-V1.2/novel_agent.py run \
  --project ~/Documents/WordLetter-Novel-Agent/projects/cet4-bb0fff11fb2a --fast
```

### 新书使用高效模式

```bash
cd ~/Documents/WordLetter-Novel-Agent-Fast-V1.2
bash start.command
```

向导新建书会自动使用高效模式；全部质量检查照常进行。

### 回退到逐章模式

如果双章长输出持续超时，在新版目录中执行（不带 `--fast`）：

```bash
python3 novel_agent.py run --project /真实项目路径
```

程序会跳过已存在文件，仅对尚未生成的章节或审校单独调用。若重连导致留下了**损坏/不完整的 JSON**，先备份它并删除该单个损坏文件，再续跑；不要删除整本书的项目目录。

## 质量边界

这是**流程调用优化**，并未证明真人阅读效果或 IPA 100% 准确；需继续执行 Story Gate、章节与词卡 AI 初审、人工内容复核、出版台真实预检与权限测试。V1.2 离线结构与模拟模型流水线已通过测试；**真实 Codex 高效模式及网络场景尚未实测**。没有“快速模式可绕过审核”的选项。
