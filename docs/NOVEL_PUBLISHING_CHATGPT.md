# 妙屋小说审稿与上架手册

这份手册给每次新开的 GPT 聊天使用。站长在聊天里提供本次稿件和相关词表，GPT 完成可以独立处理的审稿、词卡匹配、预检、打包和交接。站长用正式出版台完成需要发布者身份的操作。有授权工具的项目会话负责查询正式库或复核结果。

## 新聊天直接复制

> 请先读我给你的《妙屋小说审稿与上架手册》，按其中的规则处理本次附件。书名是【】、等级是【】、操作是【新书 / 修订】、试读章数是【】。我会附稿件和手头的分级缺词表或授权词卡资料。你可以修改和完善草稿。请核算本分类缺口，修订正文，使用授权的正式词库完成词卡匹配，校验并交付最终上传包及覆盖报告。若有资料缺失，先交付可以核实的结果，再一次性列出继续所需的最小资料。区分本地检查、出版台预检和正式发布复核。

新聊天先给 GitHub 手册链接，加上这段话和本次正文。没有读到手册时，直接把 GitHub 页面里的 Markdown 下载并附到聊天。Mac 文件要作为附件上传。可追加封面、已分配的逐章词包、该等级最新正式缺词清单、经授权且范围限于本书的词卡导出。发布者密钥只在正式出版台输入。付费正文、整书上传 JSON、用户资料、正式数据库与私有词卡工作包按私有交接处理。

## 正式词卡匹配交接

### GPT 从草稿做到可上传

站长提供草稿，即授权 GPT 为了阅读质量、语境和目标词覆盖修改正文、补写场景、调整标注和编写确实缺失的词卡。保留原稿，核对主角、人物关系与剧情。现有封面符合最终稿就沿用。书名、目标分类、试读章数和新书或修订按站长给定信息执行，已有项目默认值可以沿用并在交付时注明。

1. **确定分类与目标。** 四级、六级、考研和后来新增的每个分类都用各自的词表、正式书架和缺词清单。已有逐本词包按分配目标验收，另有单书净增要求时按该书要求执行。新增分类需先有可核实的目标词表和正式分类身份。跨等级可以复用词卡，覆盖只计入实际发布正文所在的分类。
2. **审稿并完成修改。** 先对照目标分类的正式书架估算现稿净增。同批补缺作品先分配各自负责的缺词，避免同词重复占用净增名额。为自然语境改写或补写，随后重新提取实际正文标注，核对词形、词性、义项、人物和剧情。补缺阶段优先验收首次覆盖，同时检查妨碍阅读的重复。
3. **查词卡并完成匹配。** 有授权正式词库读取能力的 GPT 直接按本书归一词头查询，跨等级查已有卡。逐义项核对原句、词性和释义。同义沿用正式 ID 和完整卡片字段，正文可以保留语境释义。词头命中先列为候选，义项明确后再确认复用。候选有冲突时继续核对，确无合适卡时补编新卡，检查释义、英美音标、双语例句及搭配。记录正文位置、临时 ID、最终 ID、结论和依据，替换全部正文引用。可跨等级复用的词卡仍只贡献本分类的覆盖。
4. **验证最终包。** 检查正式书目中的同名书与 ID，修订沿用原书版本入口。核对分类、试读、章节、封面、真实正文引用及词卡字段。用正式发布分支对应的 validatePackage 和 planOpsBookImport 验证 JSON，再核查已有卡字段一致、其余 ID 无冲突、没有临时 ID 或未处理的义项冲突。结构检查、正式代码校验、出版台预检和实际发布是不同状态。当前会话无法运行正式校验时，先保留完整待校验包，交给有能力的会话执行校验，拿到结果后再标为可上传。
5. **交付并验收。** 交付最终上传 JSON、独立封面、修订正文和一页报告。报告先列本分类当前缺词、本书预计净增、上架后预计缺词、待核项数，再列跨书重合率、书内重复率及复用、新编词卡数。站长在出版台预览核对并确认发布。确认正式发布后用同表复算实际净增。

## 词库授权与工作流

用户既有权限能读正式词库时，直接使用该通道。使用受保护的查询或资料转交工作流时，汇报具体目的、运行链接、审批用途、是否只读和下一步。先检查已有运行与产物，成功的查询结果可读时直接审义项。加密产物转交成功之后，逐项确认审稿侧能读取明细、词性和义项已核对、最终包通过校验。遇到真实的权限或产物问题时只请求能解除当前阻塞的一项操作。空结果、词头汇总、加密文件转交成功都需要各自对应的证据。每本书的常规审稿、配词、词卡核对和本地打包采用这套流程，GitHub Actions 按实际读库或转交需要使用。

需要换会话时，交接本书正文或候选 JSON、封面、分类与试读设置、按位置列出的词义明细，以及已取得的授权词卡查询结果。逐项记录哪一步已验收，接手者从第一个未完成环节继续。

## 从稿件做到出版台

1. **定版本与权益。** 确认成稿版本、所属等级、简介、试读章数，以及新书还是修订。未指定试读时按现有全书付费做候选并在交接中明确。通过正式书目确定是否已存在，修订沿用原书 ID 和版本修订入口。没有正式数据时先做预检候选，并注明同名和 ID 冲突待查。
2. **只从真实章节提取。** Word、Markdown、TXT 都先识别章节，排除制作说明、移章列表、章末词包和统计表。按章核对计划词和实际标注。分清词头与正文词形，保留可读的混合语言正文。弱语境优先改本句，无法自然安放的词退回后续选词清单。释义要和本句词性及义项相符。
3. **复用词卡。** 在有授权的正式词卡资料中按词头找候选，再按词性和正文义项核对。匹配时沿用正式词卡的 ID 和全量字段，正文标注可给更贴切的语境释义。多义词分别匹配。P0 历史词卡和候选词典可供查找及编卡。候选命中单记；新卡逐项核词性、中文释义、英美音标、双语例句。没有正式资料时交付待匹配清单与候选 JSON，按上节继续取数或交接。
4. **交付可上传文件。** 正文打包成出版台 v1 JSON。顶层有 version、book、chapters、words。book 提供稳定 ID、书名、分类和简介。chapters 从 1 连号，包含 id、number、title、preview、paragraphs。每段 segments 是普通文本或带 wordId、surface、gloss 的学习标注。words 提供对应 ID、headword、partOfSpeech、meaningZh、phoneticUk、phoneticUs、exampleEn、exampleZh 与 collocations。另交付独立封面 JPG、预检摘要、需人工处理项和缺词清单。通过正式发布分支的 validatePackage 与 planOpsBookImport 后交付最终包。只有结构校验的包标为待校验。
5. **从出版台发布。** 在正式出版台验证运营身份，进入「⑦ 上传并发布新小说」，选 JSON 与封面，点「识别文件并检查内容」。核对章节、词卡数、标注数、付费章数和缺失信息，抽点正文词卡，再点「确认上传并上架」。出现错误时先检查是否已创建草稿，继续在原草稿处理，避免生成同名书。修订和下架走对应的出版台入口。 [妙屋正式出版台](https://miaowu-english-pages.pages.dev/ops.html)
6. **复核正式结果。** 核实正式书 ID、发布状态和已发布章数。能读取正式绑定时复算净增和缺词，并更新下一批词包。只有出版台结果时，可记录站长确认的发布状态，覆盖继续挂「待实测」。页面仍未发布时保留当前正式缺口。

## 覆盖与排产

每次固定对应等级的目标词表版本。有效覆盖是目标词在该等级已发布正文中至少有一处正确、可点开的词卡绑定。正文词形按所绑定词头归并。只在字典、章末清单、草案出现的词另记。其他等级词卡可以复用，覆盖跟随本等级的已发布正文。

- 上架前正式缺词 = 目标词表 − 正式书架有效词头。
- 新书预计净增 = 本书有效目标词头 − 上架前本等级有效词头。预计剩余 = 当前缺词 − 预计净增。
- 修订或下架先按新书架重算集合。单列失去最后一处有效位置的词，以及被其他作品接住的词。
- 上架后用同表重算，报告实际净增、实际剩余和差异。书内重复标注率 =（有效目标词总标注次数 − 该书去重目标词数）÷ 有效目标词总标注次数。和书架重合的不同词另报。
- 本数按剩余缺词除以每本实际净增，向上取整。每词先分给一本做首次覆盖。先安排三本，使用真实净增校准；余词按题材重配。四级继续现有逐本逐章排产，涉及《雨夜档案》时同时计算在架与下架。考研使用项目选定的大纲版，雅思沿用项目词表，高中推动独立书架时才记录该书架覆盖。统计须注明词表版本和日期。

六级《第七个证人》的发布复核为 10 章、113 个目标词、121 处标注。正式六级书架从 883 词到 914 词，新增 31 词，当次剩余 4,493 词。四级《雨后第七码头》的稿末词数曾与真实标注不同。先按章提取正文、补回能自然写入的词，再计算整书净增。
