# 妙屋英语 WordLetter · 更新公告与历史更新日志（已确认需求，暂不开发）

**状态：产品需求已确认；不属于当前 V1.1 核心收尾开发，不创建公告表、不修改网站前台或运营台、不部署。**

## 用户已确认的规则

- 首页展示位置：**Banner 下方**，单条窄通知，不使用大横幅或打断式弹窗，不影响分类、阅读、兑换等原功能。
- 关闭规则：用户可以关闭当前公告；同一浏览器在刷新、重新登录后仍隐藏该公告；只有**发布新公告**才重新显示。编辑原公告不应当重新触发提醒。
- 首页最多显示最新一条由管理员指定为“首页展示”的已发布公告；用户关闭后不滚动播放旧公告。没有符合条件的公告时，整个通知区隐藏。
- **所有用户都可以查看历史更新公告**：包括游客和已登录用户。在独立「更新日志」页面按发布时间倒序查看仍处于已发布状态的公告；用户关闭首页通知不影响历史记录访问。
- 公告页面可从首页“查看详情”和页脚的小入口进入；暂不强行加入顶部主导航。
- 发布后可通过站内运营台自主管理：新建、编辑、保存草稿、发布、取消发布、下架、查看历史记录，并可自行控制首页是否显示。
- 运营台采用**默认折叠、紧凑列表、详情展开**，避免占据整页。栏目名称建议「更新公告管理」，前台建议「妙屋新鲜事」。
- 公告类型：功能更新、新书上架、维护通知、其他。字段：标题、摘要、正文、类型、是否首页展示、发布时间、状态。
- 首页通知适配手机，最多两行标题，显示简短摘要或日期，保留“详情”和关闭按钮；日夜主题样式统一。新发布后 7 天内可展示 NEW。
- 不需要新公告时改动网站代码。第一版**不做**公告配图、定时推送、跨设备关闭状态同步、强制弹窗、点击统计和复杂分析。
- 已下架公告不会出现在前台历史日志中，但运营台仍保留记录供管理员追溯。普通编辑不应产生新的历史公告；如果需要再次提醒用户，应独立发布新公告。

## 后续实施的安全设计约束（非开发承诺）

- 建立独立公告表、只读公开列表与详情接口、已授权运营管理接口；不能接触 `users`、`user_words`、`entitlements`、`activation_codes` 等学习/订单表。
- 用户关闭当前公告的状态建议保存为当前浏览器本地的公告 ID，不写入用户身份。换浏览器可能重新出现，属于第一版已接受的设计。
- 公告正文严格转义/过滤，禁止脚本和危险外链注入；运营修改必须有鉴权、输入长度限制、状态验证及发布审计。公开 API 不得泄露草稿、已下架内容和后台字段。
- 不允许公告影响文章发布与读者原学习进度、付费墙或编辑器。
- 只有当前 V1.1 学习状态、历史数据核验和最终上线工作稳定后，再安排该模块具体开发。
