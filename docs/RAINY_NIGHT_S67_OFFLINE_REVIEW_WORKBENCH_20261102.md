# S67｜无需手改 JSON：私有审校台可逐条记审核进度、导出与导入

继 S66 为全部 **957 条**审核单位创建了可核验的原稿 SHA-256 记录后，本轮将审校操作接入真正的**纯本地 HTML 页面**。目标是让人工审核人员能够真正完成工作，而非在大块 JSON 文本里定位词卡。

使用 `node scripts/build-rainy-night-offline-review-workbench.mjs --write-private` 生成 `private-output/rainy-night-s1-PRIVATE-HUMAN-REVIEW-WORKBENCH.html`（仅本地；文件已存在会拒绝覆盖）。

用浏览器本机打开 HTML 后：

- 在原本188个词卡、733处标注、36道题中，点击相应卡片的**填写此条审核**；
- 根据实际核对结果选择 `未审核`、`已核对` 或 `需要修改`，填写真实审稿人标识、审校说明、私人日志/证据编号；点击**保存此条到本页内存**；
- 页面顶部统计实际三类进度。完成一批后必须点**导出审核记录 JSON** 并妥善存储；关闭网页后数据不会自动保存到浏览器/云端；
- 下次使用**导入此前审核记录**，页面会检查书本ID、版本摘要、957条清单、逐项内容指纹和证据字段，防止拿旧稿件的审核记录冒充新稿。
- 如要正式检验文件内容，仍使用 S66 的 `node scripts/build-rainy-night-review-ledger.mjs --validate-private <本地文件>`。HTML端仅做可用性校验，命令行是最终结构校验。

**安全：** 所有原文和审核文件继续留在 `private-output/`，绝不部署到 Pages 或 Worker。HTML页面没有 fetch、网络提交、登录、D1 操作、浏览器持久化；CSP 禁止网络连接。即使本地记录全部标记“已核对”，也只是用户自填的审稿日志，**不是核验审稿人身份的数字签章，更不构成商业音标版权/商品发布批准**。

自动测试覆盖957项渲染、源稿指纹一致、手动选择审核/导出、旧稿错误导入拦截、离线JS语法及发布门禁 BLOCKED。后续编校人员可以用它真正开始逐条检查。
