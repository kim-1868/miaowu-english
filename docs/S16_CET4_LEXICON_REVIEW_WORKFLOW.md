# S16｜CET4 分类总词库：第一批可执行词库工单（未验证、不可发布）

日期：2026-11-01

## 用户确定的长期战略

**四级分类总词库规划约4,500个词 → 分配到多部有完整剧情的中文小说 → 每部约200目标词（一般150新词+50已出现词）→ 高价值词跨章和跨书复现 → 同一个读者账号积累唯一词卡、阅读记录与练习状态。**

**4,500是当前产品规划尺度，不是被审计的最新官方四级词表规模，也不是已购入/已导入4,500条认证数据。** 不使用来源不明或不可再分发的词库文件来凑数字。

- 产生**建议用的全局唯一候选词 ID**（例如 `lex-en-evidence`），同时保存已有的 `rns1-evidence` 私有手稿 ID 对照；**ID 没有写入当前 D1，也未更新任何已存在的用户收藏、进度或权限**；

### 本地执行（不会访问 Cloudflare）

```bash
npm run content:cet4-pool
npm run content:cet4-pool -- --json
npm run content:cet4-pool -- --write-private
npm run content:cet4-pool:strict
```

- 默认输出中文 Markdown：实际候选词数、各作品新增词/重叠词、真实《雨夜档案》章节字数/英文标注情况以及审核欠项。
- `--write-private` 写入被 Git 忽略的 `private-output/cet4-candidate-review-queue-UNVERIFIED.csv` 与 `private-output/cet4-candidate-plan-UNVERIFIED.json`，逐词包含 `candidate_id`、`draft_word_id`、词义/词性、12章出现次数、初步跨书重复、审核状态。可以由人工逐词核对；文件名含 UNVERIFIED 防止误用。
- `--strict` **现在理应失败**：因为至少词表来源、IPA和义项尚未独立审校。只有完整审校和真正商用发行签核后，才能讨论正式导入与上线；不能用单纯通过 CI 取代这些工作。

## 单词 ID 与真实数据的隔离

现有 D1 结构：
- `words(id,headword,...)` 存词卡；
- `chapter_words(chapter_id,word_id,...)` 存故事位置；
- `user_words(user_id,word_id,...)` 存个人收藏/学习状态；
- `review_events` 存用户练习记录。

这些结构能够支撑词卡跨书复用，但**自动迁移已经存在的 `rns1-` 词条或现有测试词条会影响关联数据，不应直接执行**。先形成经审校的“候选 ID → 正式稳定 ID”变更规划，校验一词多义/义项，再决定是否新建分类词表映射与安全迁移。现有测试用户的 promise 词卡和剧情回声记录必须保持原样。

## 下一个真正需要产出的内容

1. 选择合法、可靠、可复核且有版本的四级词汇数据来源，明确 lemma/词形/不同义项口径，并记录每条目标词的审校证据。**目前未完成，不能把现有188候选词全部自称官方四级词**。
2. 在生成的 CSV 里由编辑为每个词补足来源、使用等级、正确词性、当前剧情义项与英美 IPA；先审核心情节词和 Rose 共用词，再处理低复现候选词。
3. 把正式审核的 200 左右目标词按第1–12章分层，先扩充故事正文字数，再自然提高跨章节出现频次，而不是机械重复至700次。
4. 每部新作品重跑该工具，跟踪分类层面的**首次引入、跨书复现、已审核的词库覆盖率**。不能把“小说里存在这个词”误当读者实际已读或已掌握。
