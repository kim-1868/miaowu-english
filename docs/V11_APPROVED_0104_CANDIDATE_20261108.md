## 2. 01 公告正式启用的“双重显式批准”
### A. API 开关（默认关闭）
- `src/site-announcements.js` 在 `APP_ENV=staging` 保持现有功能。
- `APP_ENV=production` 只有额外明确设置 `OPS_ANNOUNCEMENTS_ENABLED="true"` 才能访问相关读写接口；没有这个变量、false 或其它值都 fail-closed 返回 404。
- 已有管理员角色、独立密钥、版本冲突、只读公开查询和草稿过滤保持不变。**/api/ops/updates/setup 只允许 staging**，不允许在 production API 自动建表。
- 当前 `deploy/production.wrangler.jsonc` 不配置这个开关，维持默认关闭；本候选不自行修改其值。

### B. 静态包开关（默认移除）
- `node scripts/build-production-assets.mjs`：仍构建原有 46 项资源，自动从首页/运营台剥离公告，既有正式构建行为不变。
- **仅用于离线候选审核**：`node scripts/build-production-assets.mjs --approved-announcements`；额外纳入 4 项 `site-updates.css`、`site-updates.js`、`updates.html`、`ops-updates.js`，保留前台/后台公告区域。这条命令只生成本地目录，无网络、无部署。
- 生产真正启用必须同时满足：从正式基线做范围隔离 + 审查公告独立表 `db/015_v11_site_announcements.sql` + 可恢复的真实备份 + 人工批准 + 正确静态构建 + 生产 Worker 显式启用开关 + 正式部署后验收。**仅打包或仅切开关都不构成完整发布。**
- 禁止将 staging 演示公告、预览运营密钥、测试 D1、自动建表的测试入口或任何演示数据复制到正式站。

## 3. 现有依赖与风险
1. **混合改动阻断**：私人 V1.1 基线并非纯 01–04。上线前必须从当前真实生产版本重新拉取固定 SHA，逐文件挑选并核对与主站其他并行开发的冲突；不能直接合并 PR #154 或整个本分支。
2. **预览环境可访问性阻断**：历史 GitHub Actions #42352852512 部署成功并验证匿名 401；但本次外部浏览器出现 Cloudflare 404 / 连接失败，没有复现预期的 401。须先在 Cloudflare Workers 复核 Workers.dev 路由/部署状态；不要推断现有预览密钥失效，更不要重复生成密钥。
3. **DB 阻断**：目前没有对正式 D1 的真实可恢复备份、015 兼容核对和增量迁移批准。严格不运行生产迁移。
4. **登录实测阻断**：读者注册/激活、第一章可选试读（单独需求）、词卡收藏/掌握、下一章进度、跨书学习状态、运营台发布都需受保护的预览真实测试账号验证。
5. **移动端阻断**：320–1920px Chromium 合成测试不代表真实 iPhone Safari / Android Chrome；关注夜读对比度、工具栏、弹层不遮挡、点击音标发音和 12/24px 极限字号。
6. **内容审核**：生词词义、IPA、例句、搭配需抽样核对，不把 UI 验收等同于完整 23 本语言质量验收。
7. **小红书/售后**：本批不集成小红书接口；站内隐私与售后文字说明另行排期，不影响本次四项选定内容。
