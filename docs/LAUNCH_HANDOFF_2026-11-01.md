## 6. 下一工作包：S9 的最小安全实现边界

目标：让**经过当前版本人工复核**的原创内容，能够受控发布/撤回；保持既有授权和审计记录。

建议拆分实现，均先写自动化测试，禁止自动在测试站上架：

- **S9-A 数据与权限模型**：生产专用管理员身份+角色分离（作者/审核者/发布者），不可复用 reviewer 门禁或 `S3_EDITOR_SECRET`；独立、追加写入的审计表；批准记录关联内容不可逆 fingerprint、独立复核人、时间和操作请求 id。
- **S9-B 审核与发布事务**：发布前重新计算 fingerprint、技术报告零阻断、人工审核记录与当前版本一致、发布者与审核者分离、防重复请求及并发修改；测试/QA/demo/示例书拒绝发布；原子切换书与章状态；付费章节继续必须服务端鉴权。
- **S9-C 撤回/恢复**：撤回默认隐藏公开内容，保留账户权益、历史收藏/复习记录和原始稿件/审计，不“顺手”删除用户购买权益；明确已购买用户的可访问与退款规则，二次确认；恢复需要重新审核并记录。
- **S9-D 图形后台**：在独立管理员权限下展示预检、审核记录、冻结版本、发布/撤回和失败原因；禁止 UI 仅凭按钮隐藏进行鉴权。
- **S9-E 测试**：无权限、跨环境、旧版签字、两人未分离、测试书、非现行章节、重复提交、故障回滚、撤回后直链与词卡绕权、购买者权益不被误删、跨设备数据完整性等。
- 开发和测试期间：**仅 Draft PR + staging + 安全假数据/模拟 D1**；未经真实验收不合并 main、不执行生产写入。
