# B1.5 · 1150 义项从待审草稿进入“可提交运营台签核”的安全门禁

本轮新增 `src/global-dictionary-editorial-signoff-gate.js` 和配套测试。

用户真实私人 1150 义项审核工作区已经整理完毕，审稿实际数据保留于 `/开发英语单词学习网站/统一词卡_待审工作区/全量1150义项_十批完整审稿/`，不可泄露到 GitHub 公共仓库。

**两步安全模型：**

1. 离线编辑每一条候选，确认中文义项、词性、UK/US IPA、原创或商用授权例句、旧卡ID原义项对应及来源权利。每一项必须填写审核依据，并记录审核人、UTC 时间、商业来源/双语例句权利证明。空白模板全部处于 hold。
2. 纯函数验证齐全的审核记录，只得到 `READY_FOR_AUTHENTICATED_OPS_FINAL_SIGNOFF` **候选**，生成不冒充已核准的 provisional sense ID。缺商业授权、修改原义项身份、遗漏例句或审核证明一律阻断。即使所有勾选齐全也 **不** 自动将 `global_dictionary_senses.approved` 改为 1；需未来真实的授权 OPS publisher 审核、记录服务端不可伪造的演员身份和来源 SHA，再执行 staging D1 事务、验证和回滚。
3. 旧 ID 合并用户学习状态属于再后续的独立签核流程。现阶段不运行 SQL、不创建正式 approved sense，不触碰 D1、付费权益和复习计划。

**不能因为 AI 给出建议、机器规则通过或用户提交 JSON 说“已审核”，就把词卡自动标记为商业课程已批准。** 后续需要在 OPS 后台实现真正的逐项审阅/分批签核，不应让手工 JSON 自行设 `approved:true`。
