**验证结论：代码级候选验收通过；真正的 Cloudflare 预览站端到端验收尚未通过。禁止合并 Draft PR #206，禁止上线正式站。**

## 一、发现并修复的风险

1. **缺少实际审过的教学词卡也能保存候选**：旧代码只凭主词头 `teaching_ready=1` 与来源状态就可能接受 V1 小说绑定，没有检查 `global_dictionary_lessons` 是否真实存在且包含对应中文释义。现已改为每个关联都验证课程表、审校状态、词头一致和小说语境 `gloss` 对应的真实教学义项；缺表、缺卡、无释义、未完成例句均阻断保存。
2. **伪造统一主词卡 ID 但替换例句**：旧版 V1 小说可能把 `words[].id` 设置成合法 `gdict_` 主词卡 ID，却提交自己修改过的释义、发音或例句。现对 ID 与 canonical entry 相同的读者主卡要求和独立审核词卡在全部教学字段（包括搭配）上完全一致，阻止越过统一词典审核。
3. **两套匹配器结果不一致导致重复人工审核**：V2 使用已审、唯一中文义项把屈折词确定为主词头后，A3.1 阶段可能重新把同个词形判成歧义。现允许仅在已校验 source/form/entryId 的情况下沿用 canonical ID 候选，A3.2 仍重新校验全部教学资料和语境，不把客户端 ID 当最终审核依据。
4. **中文 gloss 与实际词卡释义不匹配**：原先 V2 即使英文拼写唯一，也可能保留不属于该词的中文标注。现一律要求该标注命中审核过的具体义项，不会生成错误词卡。
5. **回归测试用例与升级后的判别规则不一致**：调试中发现两次测试不匹配真实业务逻辑（唯一已审义项可自动消歧；无可信义项的屈折词应以「有歧义」阻断），已同步修正并保留阻断断言。

## 五、上线级增量复核：不同义项不得被主词头错误合并（2026-11-10）

历史网站实际学习身份 `studyKey(headword, POS, meaning_zh首义项)` 是词义级：同一词义跨书共享，不同词性或中文含义的义项分别学习。新词典的“一词头一张主卡”只能统一展示卡片，不等于将其所有义项变成一个“已掌握”状态。

复核发现 B1 只读预演按 `entry_id` 聚合多条旧词卡，但 `global_dictionary_legacy_links` 目前没有义项级唯一已审标识；因此 **`record` 名词“记录”和动词“录制”不可自动合并复习计划**。本次添加 `sense_identity_unverified_groups`、逐行 `requires_sense_identity_review`、顶层 `unsafe_to_apply_without_sense_mapping` 保护，覆盖即使多个旧义项全都 `mastered` 时仍必须人工核查的情形；补充专项自动测试。原始 `user_words`、`review_events`、收藏、权益数据和在线数据库不做任何变动。

**持续阻断上线：** B1.3 必须设计并验证稳定的已审义项 ID、旧义项到新义项的显式映射、按义项的掌握/待复习/收藏同步；前端可以保留“一词一张主卡”，但不能只按主词头合并用户学习状态。当前附加指标仅用于只读诊断，不表示已经完成 B1.3 或具备可执行迁移资格。
