# 妙屋英语 · 小说文件上传与发布规范（正式运营后台）

## 最推荐的协作方式

作者仅需要准备小说，运营后台负责排版、词库关联、词卡展示、发音、草稿保存及发布检查。**上传不会自动上架**。在运营出版台 \`/ops.html\` 使用已授权的 publisher 凭据操作。

本次首版支持 \`.md\`、\`.txt\`、符合 S3 内容规范的 \`.json\`；\`.docx\` 将在单独版本实现，暂不要直接以 Word 文件上传。Word 可以先另存为 UTF-8 TXT。

## Markdown / TXT 示例

~~~text
第一章：陌生来信
凌晨的 hospital 安静下来，她将 evidence 放进了口袋。
她打开 [[record|记录]]，发现了第二个名字。

第二章：背后的秘密
那个 record 仍然藏在 hospital 的旧档案里。
~~~

- 一行文字作为一个自然段；空行可作为视觉分隔
- 用“第一章/第二章”或 \`## Chapter name\` 识别章节；如果没有章节标题，作为单章
- 英文词会匹配同一等级的**已有词库**，若匹配成功就自动变成可点词汇，显示释义、词性、UK/US 音标和发音入口
- 对多义项或容易混淆的词，可用 \`[[word|精确中文释义]]\` 指定已存在的词卡。找不到、仍存在歧义时将拒绝导入并列出具体位置，不会暗中生成错误音标
- 词库外的普通英文保留为正文，并在检查报告中提醒；如需要它也成为学习词，需先提供词卡
- 新词可额外上传 JSON 数组（见下方格式），导入器不会虚构解释、音标或例句

## 补充词卡格式

~~~json
[
  {
    "id": "vocab-hospital-n",
    "headword": "hospital",
    "meaningZh": "医院",
    "phoneticUk": "/ˈhɒspɪtəl/",
    "phoneticUs": "/ˈhɑːspɪtəl/",
    "partOfSpeech": "n.",
    "exampleEn": "She worked at a hospital.",
    "exampleZh": "她在一家医院工作。",
    "collocations": []
  }
]
~~~

上面只是用于演示字段的词卡，正式音标、释义和考试词表归属必须在商业发布前实际核对。请勿将演示词条作为已审定的商品词库。

## 正式运营台流程

1. 验证 publisher 运营身份。
2. 在“上传新小说”选择文件和等级，可选补充词卡。设置书名、内部书籍编号及试读章节数。默认**零免费章节**。
3. 点击“识别文件并检查内容”。确认章节、可点击词汇数量、异常词、缺失英美音标、例句与平均每段词汇量。
4. 点击“导入为新草稿”。服务器在一个事务中保存书籍、章节、词卡和词汇位置，书籍状态始终为 \`draft\`，读者无法查看。
5. 通过运营台的书籍目录选择新草稿，核对实际阅读效果、单词弹窗、浏览器发音、生词本与付费权限。
6. 完成真实人工审核并保存版本绑定的审核记录，再单独输入书名确认正式发布。
7. 发布后分别用已购和未购账号检查，已购者可读全部付费章节，未购者无法取得正文。

## 当前版本限制

- **新书和已有草稿是两个独立操作。** 新书点击“导入为新草稿”；《雨夜档案》这样的已有未发布草稿，先在上方选中它，点击“使用当前选中草稿的书名和编号”，上传新版文件完成预检，再点击“替换当前未发布草稿”。版本指纹不符、章节ID变化或原有英语锚点丢失时会自动拒绝。已正式发布的书籍暂不可覆盖。
- 本次为书籍结构和已有词卡的**自动关联**，不是自动生成高质量词义、IPA 或剧情回声题库。新词需要完整词卡数据；剧情回声内容需要独立校验
- 本次不直接解析 \`.docx\`，只支持 JSON / Markdown / TXT
- 草稿导入不会修改已购权益、激活码、学习记录，也不会自动发布
- 当前单次服务器正文上限2MB、60章、500个词卡、10000处标注；后续将根据真实用户文稿做分段上传和续传
- 已发布图书修改须保留老版本和会员学习数据，不能依赖重新导入覆盖

## 为什么这样设计

正文文件是作品来源；词卡是全站复用的学习内容；发布审核是单独的商品生命周期操作。三者分离，才允许站长长期自助更新，而不用每本书再执行一次临时 SQL。
