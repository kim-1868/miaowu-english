# 私人候选整体验收门禁（公共开发 / 私人整合）

> 2026-11-07 起采用。该工作流专用于私人仓库最后的整合检查，**不会部署线上**。

## 分工
- **公共仓库 `miaowu-english-public`**：可公开的 UI、样式、通用组件、合成数据测试、SHA-256 交付包。公共 `main` 通过 CI 后生成 `wordletter-public-ui-<SHA>` GitHub Actions 构建产物。
- **私人仓库 `miaowu-english`**：真实小说、词库、用户订单与激活权益、鉴权、D1、发布密钥及最终发布。禁止公库访问私人仓库，禁止将任何 Secrets 或真实用户数据放公库。
- 公共构建只是待整合代码，不是线上发布。整合前必须检查**公共交付完整 SHA、manifest 中每文件 SHA-256、私人目标最新 SHA、4 个已存在版本差异及真实权限回归**。不允许直接全量替换私人网站前端或自动改写数据库。

## 私人 Actions 流程

本文件对应私有 `.github/workflows/private-candidate-integrated-qa.yml`，应放在私有默认分支，使用户在 Actions 中可以手动选择它，输入**精确 40 位候选提交 SHA**，在一个独立、无 Cloudflare 凭据的运行里执行：

1. 检查私人候选 SHA；不保留 checkout 凭据；
2. 完整 `npm run check` / `npm test`（真实业务的离线回归，不把敏感代码传到公共库）；
3. 生产配置检查、公开前端整合构建、Pages 和 Worker 离线 `--dry-run`；
4. 输出候选 SHA 与不部署/不连接正式 D1 的验收声明。

**此工作流用于候选阶段，替代每次开发 PR 都跑 S1 + 生产 dry-run 的重复重型检查；不是最终生产审批，也不会自动触发部署。** 准备上预览前，必须另行验证测试 D1 和账号权限；准备上正式站前仍需用户明确批准、备份恢复方案、真实路由与权限全链路验收。

## 当前限制与待办

- 私人 CI 自动触发规则必须单独修改并做 PR 验证。单独新增本工作流不会立即减少现有 PR 运行次数。
- 需要用户或授权执行人从 GitHub Actions 手动触发私人候选整体验收；它不应在公共仓库自动取得私人代码。
- 私人预览发布工作流仍需结合同期其他网站开发协调；本轮不改变它的自动部署触发，避免其他 Agent 工作突然不出现在预览站。
- GitHub Actions 实际计费分钟以 GitHub Billing 为准，不能使用最近 100 次采样的运行数代替月账单。
