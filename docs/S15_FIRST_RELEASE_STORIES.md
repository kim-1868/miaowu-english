# S15｜四级首发作品与《玫瑰未落幕》保留方案

2026-11-01　状态：**编辑策划 + 本地代码草稿，非公开正式发售**

## 本轮用户选择

用户明确提出：目前网站的两章测试小说 **《玫瑰未落幕》“也还可以，可以保留”**。因此不可将该作品作为无用 fixture 清理，更不能因《雨夜档案》开发而覆盖其章节、词卡或已展示的书名。

### 已核对的当前事实

- 《玫瑰未落幕》在 `public/app.js` 的 `BOOKS` 里标为 `status:'demo'`，两段章节题名分别是 **《一纸协议》**、**《藏在照片里的名字》**；共两章**临时测试文案**及12个标注词条。
- 演示词卡和本地阅读记录使用浏览器本地状态，**不是**真实 D1 云端文学商品，也不等于消费者已获得付费书籍权益。
- 当前主要书架从 `/api/books?category=...` 拉取 **D1 已发布书籍**。旧 Rose 演示虽然还在 JS 中，原先却没有从正常动态书架显示，用户后续可能以为它被删掉。
- 因此在此开发分支添加《玫瑰未落幕》**独立的“互动演示 · 非正式商品”书卡**：只在 CET4 书架出现，点开第1章本地互动体验。D1 来源优先；如果未来真实 D1 里出现 `rose` 或同名已发布书目，就**不重复显示**本地演示卡。没有重新定义付费章节权限，也没有把本地演示伪装成 D1 云端学习。
- 已有 `openChapter` demo 函数的第2章仍会检查现存四级测试权益。这只是旧演示交互流程，不得宣传为服务器级付费正文保护；**正式付费正文必须全部存在 D1 并通过 Worker 实时鉴权**。

## 两条内容线同时保留，但不能混淆状态

| 故事 | 内容方向 | 目前稿件 | 下一步 | 能否真实收费 |
|---|---|---|---|---|
| **《雨夜档案》** | 都市轻悬疑、旧书店匿名信与失踪姐姐 | 12章完整连续剧情初稿，188个候选目标词，220次词汇标注；跨章节重复词22个 | 审校剧情、英语词项/CET4等级、IPA与发音、阅读时长、互动题库 | **不能**：仍为 `draft-`、未审核 |
| **《玫瑰未落幕》** | 情感悬疑／离婚逆袭方向 | 2章临时演示文本、12个演示词条 | 原始样章留存，进行单独的故事完整性设计、章节扩写、词汇规划、编辑与验证，随后再决定是否作为正式四级第二部 | **不能**：当前仅浏览器 demo |

不能拿《玫瑰未落幕》两章试验文本作为已经完成的正式商品宣传，不把两部作品拼成一部小说，也不删除用户已认可的原有体验。

## 合理的内容推进次序

1. **保留 demo 原样入口**：能看到同名书卡、能点开第一章演示、点击词汇查义与发音；所有徽标明确显示“仅供体验／非正式商品”。记录在 `content/editorial/launch-candidate-registry.json`，用自动化回归防止未来被意外删除。
2. **优先完成《雨夜档案》**：逐章审核故事连续性、188候选词的类别/语境适配、英美IPA；至少完善高价值目标词在后续章节的自然复现。不能只凭覆盖率认为读者已掌握单词。
3. **规划《玫瑰未落幕》升级稿**：从现有“协议、照片、身份”等线索发展为真正完整故事，先完成结构大纲与章节目标，再生成词库/正文/剧情回声练习；保留现有两章作为参考素材但允许按剧情质量审校重写，**不自动取代当前 demo**。
4. **同类权益不重复出售**：两部未来都审查发布到 CET4 分类时，已有 CET4 分类权限的同一账号可直接阅读两部的受限章节；销售承诺需要明确后续新增作品和服务期限。
5. **单独正式内容包**：审校完成后，为每部书在 D1 创建不同的真实 bookId、chapters 和词卡。导入前做 D1 只读备份、私有草稿包校验和付费章节越权测试；不得将受限正文写进 `public/`。

## 下一轮审校门槛

《雨夜档案》：章节自然阅读时长、伏笔兑现、人物与时间轴一致、候选词词性/上下文/音标、跨章复现、复习题质量，全部可追溯审查。

《玫瑰未落幕》：先确定人物设定、章节数量、故事终局、原有两章哪些内容保留；目前**不强行给出“已完成12章”或“已符合四级考试大纲”的标签**。
