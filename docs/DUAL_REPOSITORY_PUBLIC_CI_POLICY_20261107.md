## 2. 后续开发的默认规则

1. **公开优先**：每个新需求先分类。页面展示、样式、响应式、通用组件、纯函数、可脱敏测试，以及不暴露商业内容的基础功能，默认在公共仓库开发、评审、自动测试。
2. **敏感留私**：未公开书稿与内容包、词卡/词库源文件及审核结果、内部编辑运营流程、真实数据、数据库迁移、生产授权与部署操作，只在私人仓库实施和验收。
3. **交界处采用接口契约**：公共仓库只包含不涉密的接口定义与模拟数据；真正的服务端鉴权、D1、付费墙、订单和激活码验证留私人仓库。接口契约变更应配合回归测试。
4. **每次公开前审核**：检查文件内容、Git 历史、Actions 日志、测试夹具、构建产物、依赖锁文件、图片元数据以及潜在令牌；通过后才将**允许公开的单个文件/清洁新提交**放到公共仓库。
5. **不要直接复制仓库历史**：旧分支/提交可能包含草稿、未公开词库、配置或临时凭据。公共仓库从全新历史开始，禁止 fork、mirror、push --mirror、git subtree --history、批量复制等直接迁移方案。
6. **正式/预览环境隔离**：公共 CI 默认只做离线检查和可公开静态构建；现有正式 Pages/Workers/D1 发布链、测试 D1、现有预览 URL 与账号数据保持原样，未经单独审查不得让公共仓库持有 Cloudflare 部署凭据。
7. **避免双重 CI 消耗**：普通 UI 修改优先在公共仓库跑标准 GitHub-hosted runner；私人仓库的重型集成、安全、数据和生产发布检查按需触发。GitHub 免费总分钟的公共规则不适用于私人仓库、较大型或自托管运行器的所有场景。
8. **验收标准**：发布前需验证登录、分类权益、词卡统一 ID/义项、学习记录、复习、运营公告、订单与后台功能，不允许仅凭公共仓库 CI 通过就宣称线上整合成功。
