## 一、已审核词义在隔离 SQLite 的真实读写闭环

- 新增 scripts/v11-local-reviewed-writeback.mjs，**不由正式 Worker 或 Pages 导入**。
- 必须先有经语境签署的 reviewed_sense_groups / reviewed_sense_aliases，并通过旧学习记录冲突与权限审查，才能对独立本地 SQLite 启用 writeback。
- 词卡、快速刷词、听音拼写、剧情回声模拟使用相同学习义项；每次动作在单个 SQLite 事务中更新已审核共享 schedule、每个旧文本 studyKey 的兼容 schedule、当前有权词卡的 user_words；成功答题仅新增一条 review_events，保留原 word_id 和 Echo 原 chapter_id。
- 章节已完成才可用剧情回声答题；同词不同词性选项不能误判正确；其他账号、未购买或作废权益不允许更改。
- 显式标记掌握、取消掌握/取消收藏和后续复习计划联动。重复 requestId 只确认原结果，不重复记答题；写入中途报错则回滚整个事务，旧学习行/阅读进度/历史答题记录保留。
- 所有功能默认不启用：本模块只在本地 SQLite 中运行；**线上尚未迁移 014、未切换已审核义项、未改正式 D1**。

执行：

    node --experimental-sqlite --test tests/v11-p5-reviewed-sense-shadow-views.test.mjs

## 二、现有书库真实资料边界与局部数据检查

当前仓库 content/operations/published-book-story-tags-v38.json 的来源声明为 2026-11-06 生产只读元数据快照，**记录 23 本书的标签与书名**；该记录不是 23 本完整正文或词卡库。

当前 GitHub content/release-packages 只能找到 **2 份完整 JSON 书籍包**：
- 《离婚后，前夫公司成了我的客户》，6 章，49 条词卡；
- 《替嫁当天，我撕了婚约》，6 章，56 条词卡。

两份文件有 **38 个完全相同的旧 wordId**，词目/词性/中文释义字段未发现冲突。这仅证明仓库内两个文件的机械字段一致，不证明词义、例句、音标或商业正式 D1 当前数据已经人工逐一确认。

脚本 scripts/v11-p5-local-corpus-audit.mjs 仅扫描仓库内容：检查引用词卡存在、重复 wordId 的词义字段变化、音标差异与候选不同 ID 同形同义，输出统计数字，不修改任何内容，也不自动批准合并。其结果永远标记 PARTIAL_REPOSITORY_CONTENT_ONLY_NOT_23_BOOK_SIGNOFF。仓库无其余 21 本的完整对应包时，不得声称全库审核已完成，也不得把 GitHub 历史文件直接当成当前生产库。

执行：

    node scripts/v11-p5-local-corpus-audit.mjs
    node --experimental-sqlite --test tests/v11-p5-local-corpus-audit.test.mjs
