## 2. 当前实际部署架构

```text
用户浏览器 -> miaowu-english-access-check.pages.dev
  -> Pages Advanced Mode _worker.js
  -> Service Binding STAGING_ORIGIN
  -> Worker miaowu-english-staging
  -> stagingGate -> 读者身份与权益验证 -> 测试 D1
```

- Pages 没有 D1 直连、没有读者密码 Pepper、没有 reviewer 密钥，独立公网探针不读取账号数据；
- Worker 仍绑定 `miaowu-english-test`；保留原测试数据和旧 Worker 入口；
- 当前 Pages Git 构建绑定 `dev/pages-access-network-poc`，独立于 Worker 的 `release/staging-rc-20261101-dryrun-fixed`；
- Pages 的 **Production branch 仅代表 Cloudflare 部署环境槽位**，整套系统仍是受 reviewer 保护的测试环境；
- 最小自动化回归命令：在 `pages-poc/` 执行 `npm test`、`npm run build`；另有不使用账号密钥的 `npm run smoke:public`，从运行该命令的公网出口检查两个公开探针与未认证 401 gate。**该 CLI 不代表中国大陆三网测速。**

## 4. 不涉及密钥的公网安全探针

此脚本仅检查公开网络与未经预览授权的请求：

```bash
cd pages-poc
npm run smoke:public
```

脚本读取两个公开探针后，**无 Cookie** 请求 `/`、`/api/health`、`/api/chapters/qa-cet4-paid`，测试期预期为 401 reviewer 拦截。脚本不会收集账号、IP、密码、激活码或正文，也不执行数据写入。若结果是 200 应立即暂停发布并检查保护配置。外部网络或第三方监测平台不能带私有 Cookie。

## 5. 建议的下一批工作与顺序

1. **安全补测：** Pages 新入口下无读者账号不能读付费章节；有其他分类权益不能读四级；跨账号学习记录严格隔离；服务绑定缺失时全部受保护页 fail-closed。此类测试优先自动化，真实账号负例需要独立测试身份。
2. **稳定性：** 每个运营商至少 2 次不同时间段的无 VPN 实机访问。记录是「能打开」还是「完成登录+读写」，不能把只测首页当作全链路成功。
3. **内容发行：** 审核12章原创悬疑一稿、全部188词词性/考试范围/音标/英文发音与例句，建立可复核的编辑记录与词库校对流程。
4. **正式环境设计：** 建立独立生产库、正式发布/备份/回滚方案；仅在审批通过后创建，避免误用已有 QA。
5. **品牌域名：** `.com` 优先，名称可用性和续费价需以注册商当前页面核实；先用 Pages 原域名维持测试。选定域名后，在内地网络重新测试所有接口。
6. **支付闭环：** 选国内合规商户收款服务商，先做模拟订单及幂等权益，完成退款/售后方案再考虑真实交易。
